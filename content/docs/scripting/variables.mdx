Variables fill themselves in when the command runs. Most message systems share the core guild, user, channel, and date variables below. Context-only variables only appear in systems that actually provide that data.

If a value does not exist in the current context, bored usually falls back to `n/a`.

<Callout type="info" title="Aliases">
`{guild}` resolves to the server name, and `{channel}` resolves to the current channel name.
</Callout>

<Callout type="info" title="VoiceMaster announcements">
In VoiceMaster announcements, `{user.*}` refers to the channel creator, and `{channel.*}` refers to the newly created voice channel.
</Callout>

 Ticketing variables are available in ticket welcome message content.

| Variable | Output |
| --- | --- |
| `{user}` | Ticket opener mention shortcut. |
| `{ticket.id}` | Internal ticket record ID. |
| `{ticket.number}` | Ticket number without padding. |
| `{ticket.number.padded}` | Ticket number padded to four digits, such as `0007`. |
| `{ticket.channel}` | Ticket channel mention. |
| `{ticket.channel.id}` | Ticket channel ID. |
| `{ticket.channel.mention}` | Ticket channel mention. |
| `{ticket.creator}` | Ticket opener mention. |
| `{ticket.creator.id}` | Ticket opener ID. |
| `{ticket.creator.mention}` | Ticket opener mention. |
| `{ticket.creator.name}` | Ticket opener username. |
| `{ticket.creator.display_name}` | Ticket opener display name. |
| `{panel.name}` | Ticket panel name. |
| `{panel.button_label}` | Public button label for the ticket option the member clicked. |

Ticket welcome messages can also use the shared variables from the `Guild`, `User`, `Channel`, and `Date & Time` tabs above.

In ticket welcome messages, the shared user variables refer to the ticket opener and the shared channel variables refer to the created ticket channel.

Ticket channel naming is separate from the normal variable system. See [Ticketing customization](/ticketing/customization#channel-names) for the built-in formats.

Last.fm variables are only available in Last.fm custom embeds and use Last.fm-specific context instead of the normal Discord user context.

| Variable | Output |
| --- | --- |
| `{user.name}` | Last.fm username. |
| `{user.avatar}` | Last.fm profile picture. |
| `{user.plays}` | Total Last.fm scrobbles. |
| `{proper(user.plays)}` | Total Last.fm scrobbles as a formatted number. |
| `{user.artist_crown}` | Crown marker when the user holds the artist crown. |
| `{user.url}` | Last.fm profile URL. |
| `{author}` | Discord author name and discriminator. |
| `{author.name}` | Discord author username. |
| `{author.nickname}` | Discord author nickname. |
| `{author.discriminator}` | Discord author discriminator value. |
| `{album.name}` | Current album name. |
| `{lower(album.name)}` | Current album name in lowercase. |
| `{album.url}` | Current album URL. |
| `{album.cover}` | Current album cover image. |
| `{track.name}` | Current track name. |
| `{lower(track.name)}` | Current track name in lowercase. |
| `{track.status}` | Listening state, such as `is listening to` or `last listened to`. |
| `{track.nowplaying}` | `true` while the track is currently playing, otherwise `false`. |
| `{track.played_at}` | Unix timestamp for when a previous scrobble was played, or `n/a` while currently playing. |
| `{track.url}` | Current track URL from Last.fm. |
| `{track.spotify_url}` | Current track URL from Spotify. |
| `{track.release_date}` | Current track release date from Spotify, with Last.fm album metadata as fallback. |
| `{track.duration}` | Current track duration from Spotify, with Last.fm track metadata as fallback. |
| `{track.plays}` | Current track playcount. |
| `{proper(track.plays)}` | Current track playcount as a formatted number. |
| `{artist.name}` | Current artist name. |
| `{lower(artist.name)}` | Current artist name in lowercase. |
| `{artist.plays}` | Current artist playcount. |
| `{artist.url}` | Current artist URL. |
| `{artist.image}` | Current artist image. |

`lower(...)` and `proper(...)` only apply to Last.fm custom embeds.
