## Why use fake permissions?

Fake Permissions are useful when you want staff to use bored for moderation, but you do not want them holding the real Discord permissions behind those actions. This gives you tighter control over how moderation is done and reduces the chance of staff bypassing bored through native Discord tools.

## How do fake permissions work?

When a role is given a fake permission such as `ban_members`, members with that role can pass bored's permission checks for commands that require it. That does not give them the native Discord permission itself, so the built-in Discord action stays unavailable unless they already have the real permission through Discord.

## Access

<Callout type="warning" title="Server owner only">
Only the **server owner** can manage fake permissions.
</Callout>

`fakeperms` and `fp` work as aliases for `fakepermissions`.

## Finding the permission you need

Use `help (command)` to see what permission a bored command expects. Fake Permissions should match that permission name exactly.

## Allowed fake permissions

These are the fake permission names currently supported by bored:

- `administrator` — allows full command access anywhere bored checks for administrator.
- `ban_members` — allows ban commands that require ban permissions.
- `kick_members` — allows kick commands that require kick permissions.
- `manage_messages` — allows commands that require message-management access.
- `moderate_members` — allows timeout and similar moderation commands.
- `manage_guild` — allows commands that require server-level management access.
- `manage_channels` — allows commands that require channel management access.
- `manage_roles` — allows commands that require role management access.
- `manage_nicknames` — allows nickname management commands.
- `manage_webhooks` — allows webhook-related commands that require webhook management access.
- `manage_expressions` — allows expression and emoji management commands.
- `mention_everyone` — allows commands gated behind mention-everyone permission checks.
- `view_audit_log` — allows commands that require audit-log access.

## Add fake permissions

<Tabs items={["Syntax", "Example"]}>
  <Tab>

```text
fakepermissions add (role) (permissions)
```

  </Tab>
  <Tab>

```text
fakepermissions add @admin ban_members, kick_members
```

  </Tab>
</Tabs>

You can separate permission names with commas or spaces.

## Remove fake permissions

<Tabs items={["Syntax", "Example"]}>
  <Tab>

```text
fakepermissions remove (role) (permissions)
```

  </Tab>
  <Tab>

```text
fakepermissions remove @admin ban_members, kick_members
```

  </Tab>
</Tabs>

You can separate permission names with commas or spaces here as well.

## List fake permissions

<Tabs items={["Syntax", "Example"]}>
  <Tab>

```text
fakepermissions list [role]
```

  </Tab>
  <Tab>

```text
fakepermissions list @admin
```

  </Tab>
</Tabs>

If you leave the role out, bored lists every configured fake permission in the server.

## Reset all fake permissions

```text
fakepermissions reset
```

This removes every fake permission entry in the server after a confirmation prompt.
